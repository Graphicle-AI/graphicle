Build with Graphicle

One project. Every interface.

The browser, CLI, MCP server and SDKs use the same project data and authorization. Original evidence remains separate from draft and reviewed memory.

1.Start a local workspace

Install a release (brew install graphicle-ai/tap/graphicle, or a release archive), or build the native CLI from a checkout of the source repository. Use client and server documentation of the same version.

The service binds to loopback. For a hosted deployment, use HTTPS through the supplied reverse proxy configuration and give each person or agent its own access key. Public workspace creation is disabled in hosted mode.

These steps build Graphicle Core. graphicle --version and the build.info operation report the running edition and its capabilities.

2.Connect an agent

For HTTP MCP use /mcp/WORKSPACE_ID/PROJECT_ID, or /mcp/WORKSPACE_ID for every project of the workspace the key can read, with the X-Workspace-Capability header. Create an agent credential instead of sharing an owner credential. The Agents & API page checks initialization, tool discovery and project access. An external agent still needs its own connection.

3.Call the versioned API

Set GRAPHICLE_URL, GRAPHICLE_WORKSPACE, GRAPHICLE_PROJECT and GRAPHICLE_KEY in your environment. Never place a capability in a URL or a frontend bundle.

The URL selects the repository. Arguments cannot supply another repository_id or workspace_id. Results and errors are JSON. The OpenAPI document describes the transport; MCP tools/list publishes tool argument schemas. The generic command API exposes additional operator and experimental commands; those schemas are not all covered by this OpenAPI document.

SDKs

Both clients are source packages in the repository; neither is published to a package registry.

SDKs expose evidence retrieval, source reads and graph history. They do not automatically retry mutations. A timed-out write may have completed; inspect current state before resubmitting.

Usage, limits and data ownership

Owner-only GET /v1/workspaces/WORKSPACE_ID/usage returns UTC counters and recorded provider token usage. Set a monthly HTTP request budget with POST /v1/workspaces/WORKSPACE_ID/budget and {"monthly_requests":10000}. Null removes your cap.

Limits are enforced atomically across authenticated HTTP routes and MCP tool calls. Failed requests consume the request budget. Sign-in, navigation, usage, export, cancellation and deletion remain available. A 429 includes Retry-After until the next UTC month. Local CLI calls and background work are separate; workflows have their own model budgets. These counters are not a provider invoice or a global token spending cap.

What the product does and doesn’t establish

Citations identify recorded sources; a limited search is not a proof that a fact is absent. Static graph edges indicate possible impact, not program correctness. A suggested test is not a passed test. Deletion receipts cover the stores named in the receipt, not external backups or trained weights.
